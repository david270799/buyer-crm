## Решения владельца, которые надо учесть (из переписки)
- Реалистичный телефон: настоящие пропорции экрана, рамка корпуса, вырез под камеру, боковые кнопки; телефон чуть меньше, чтобы осталось место под заголовки.
- Заголовки без тире. Переходы плавные (движение камеры, сдвиг, масштаб), не как слайдшоу.
- Сцена открытия: нажатие «Открыть CRM» → снизу вверх выезжает окно приложения → загрузка → страница. Экран пароля не показывать.
- Звук динамичнее, у каждого действия свой звук: входящее сообщение, нажатие кнопки/вкладки, листание ленты (шорох на время скролла), набор текста (клавиши в такт буквам), распознавание ИИ (сканирование + успех), подчёркивание различий (заметный акцентный звук), смена статуса, выезд окна и загрузка, переходы, финальный аккорд. Плотный бит в музыке. Все звуки синтезировать скриптом (numpy), привязывать к тем же таймингам, что и действия на экране (`timeline.py`). Громкость около -16 LUFS.
- Сравнение клиента и администратора (сцена 6) показать подробно: анимация подчёркивания, подписи-выноски, у клиента только цена, у админа закупка, прибыль (подсветить зелёным), ссылка на магазин, внутренняя заметка, кнопки управления. Нажатие «На склад» делать настоящим кликом в админ-окне, шкала у клиента плавно сдвигается (анимация шкалы только для видео).
- Сцену ИИ рисовать как концепт: кнопки «Распознать по фото» в приложении НЕТ (в продукте распознавание работает только через бота). Не выдавать за готовую функцию.
- Финал: только «Buyer CRM», без контактов.
- Фото владельца: `brag-output/work/assets/`. 10 позиций (список в конце `scenario-v3.md`). Файлы `*c.jpg` уже очищены от интерфейса магазинов. Фото отправки (склад со стопкой коробок) лежит в `brag-output/work/assets/11.jpg`: используй его как фото отправки (в приложении у отправки есть поле «Фото»).

## Как запускать (подробно: `brag-output/work/README.md`)
1. venv + `pip install -r backend/requirements.txt numpy playwright`; `cd web && npm ci && npm run build`.
2. `bash brag-output/work/restart.sh` (запускает сервер с данными видео). ВАЖНО: перед каждым полным рендером перезапускать сервер.
3. Внешний интернет закрыт: `render.py` блокирует внешние запросы, чтобы не зависать на шрифтах и скрипте Telegram.
4. Проверяй кадры: `python render.py 13.8 41 ...` (времена в секундах), смотри картинки, исправляй переполнения, наложения, плохую контрастность и «мутные» наложения слоёв при переходах.
5. Полный рендер в фоне (`nohup`), потом `python audio.py`, затем ffmpeg (команда в README). Кадр 0 заменить постером.
6. Закоммитить и запушить после каждого законченного куска. Кадры (`frames/`) и `audio.wav` в git не класть.

## Ловушки
- `pkill -f` и `ps | awk` с шаблоном, совпадающим с текстом самой команды, убивают собственную оболочку (код 144). Убивай по PID, а слово из команды в шаблон не вставляй.
- Окна приложения в iframe должны быть одного адреса (localhost): роль клиент/админ задаётся по имени окна (init-скрипт). 127.0.0.1 в iframe не грузится.
- Не изменяй код продукта (backend/web) без согласования: видео это отдельная работа.
- В отчёте честно напиши, что в видео концепт (кнопка ИИ, плавная шкала), и что не проверено (звук на слух).

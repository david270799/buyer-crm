## Что сделано

* **Бэкенд:** слои domain → storage → repositories → services, тонкие бот и API; audit log; роли
  (админ из env, клиент из `client_info/main_client`), проверка роли на входе и в сервисе.
* **Деньги:** ledger `transactions`, баланс KRW/USD, курс; `/buy` списывает один раз, `/cancel`
  возвращает один раз; перезаказ `/rebuy` и стоимость доставки `/shipcost` двигают только разницу;
  после отправки возвратов нет; пополнения и корректировки идемпотентны. Проверено тестами с
  параллельными потоками на всех трёх хранилищах.
* **Отправки:** `/cargo` и форма в Mini App (выбор заказов → модалка), вес, коробка, трек, фото,
  стоимость (списывается с баланса).
* **Хранилище:** SQLite на сервере по умолчанию (память + синхронная запись каждого коммита),
  файл-замок, read-only режим для инструментов, ночная копия админам в Telegram, CLI копий и
  восстановления. Firestore — опционально.
* **Заказы по фото:** квадрат 1:1 на белом, WebP ≤ ~500 КБ + миниатюра, Gemini со строгой проверкой,
  одно сообщение → один заказ, бот молчит в группе, вопросы админу в личку, заказы от помощников,
  `/add`, `/setclient`, порядок номеров при параллельной обработке.
* **Номера заказов:** N1, N2, … (заглавная N, с единицы).
* **Mini App:** клиент (только чтение) и админ, веб-панель на компьютере (сайдбар + таблица),
  колокольчик (важные / все), история заказа, перезаказ, уведомления в личку (выкл / только админам /
  клиенту), ссылки «Открыть в CRM».
* **Развёртывание:** Dockerfile, docker-compose с Caddy (HTTPS), `deploy/setup.sh` (swap, Docker,
  вопросы про ключи со скрытым вводом, проверка ключа Gemini у Google, запуск, проверка бота),
  `crm.tools.doctor`.
* **Последние исправления (28.09):**
  * compose закрепляет `DATA_DIR=/data`: пустая строка в `.env` ломала путь к базе;
  * `DOMAIN` необязателен;
  * ключи Gemini формата `AQ.` принимаются;
  * Mini App больше не остаётся пустой: заголовки кеша, экран загрузки, `ErrorBoundary`;
  * понятная ошибка «клиент ещё не назначен».
* **Документы:** README, docs/architecture.md, docs/deploy.md, docs/guide.pdf, исходное ТЗ
  (docs/spec-original.md), CLAUDE.md, этот файл.

## Переменные окружения и ключи (без значений)

Все настройки — в `.env` на сервере (`/opt/buyer-crm/.env`). Шаблон с комментариями — `.env.example`;
`deploy/setup.sh` заполняет основные строки сам.

| Переменная | Нужна | Что это | Где взять |
|---|---|---|---|
| `BOT_TOKEN` | **да** | токен Telegram-бота | @BotFather → `/mybots` → бот → API Token (перевыпуск: `/revoke`) |
| `ADMIN_TELEGRAM_IDS` | **да** (можно пусто при первом запуске) | числовые Telegram ID админов через запятую | написать боту `/start` или `/whoami` — он покажет ID |
| `GEMINI_API_KEY` | желательно | ключ распознавания фото (начинается с `AQ.` или `AIza`) | https://aistudio.google.com/apikey → Create API key |
| `GEMINI_MODEL` | нет | модель Gemini (по умолчанию `gemini-2.5-flash`) | — |
| `DOMAIN` | для Mini App (compose/Caddy) | домен или поддомен с A-записью на IP сервера | регистратор домена |
| `MINI_APP_URL` | для Mini App | `https://<домен>/`; бот ставит кнопку «CRM» | setup.sh выводит из `DOMAIN` |
| `ALLOWED_CHAT_IDS` | нет | ID групп (−100…), где бот работает | бот присылает ID группы админу при добавлении |
| `WEB_ORIGINS` | нет | адреса фронтенда, если он размещён отдельно (CORS) | — |
| `INIT_DATA_MAX_AGE_HOURS` | нет | срок действия входа в Mini App, по умолчанию 24 | — |
| `PORT` / `HOST` | нет | порт и адрес сервера (8080 / 0.0.0.0) | — |
| `RUN_BOT` | нет | `0` — только API без бота | — |
| `STORAGE` | нет | `sqlite` (по умолчанию) или `firestore` | — |
| `DATA_DIR` | нет | папка базы, фото и копий; в Docker всегда `/data` (том `crm_data`) | — |
| `BACKUP_TO_TELEGRAM` | нет | `1` — ночная копия базы админам в личку | — |

| `LOG_LEVEL` | нет | уровень логов (INFO) | — |

| `FIRESTORE_EMULATOR_HOST` | только тесты | адрес эмулятора Firestore | ставит `firebase emulators:exec` |
